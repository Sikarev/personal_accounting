## 2. Принятые решения

Не пересматривать без явного запроса пользователя. Обоснования — в указанных документах.

**API** ([api.md](api.md)):
- Префикс `/api/v1`. JSON в camelCase. Деньги — целые минимальные единицы плюс код валюты, суммы в API положительные.
- Ошибки — `application/problem+json` с полем `code`:
  - ошибки данных → 422 `validation_failed` с `errors[]` по полям (путь через точку);
  - неразбираемый запрос → 400.
- Объект чужой семьи → **404**, а не 403: факт существования не раскрывается.
- Схемы тел запросов в контракте — с `additionalProperties: false` (проверяется тестом).
- Тип `date` в sqlc → `time.Time`. `numeric` → `pgtype.Numeric`, в API передаётся строкой (окончательно решится на этапе 4).
- `middleware.RealIP` убран намеренно. Реальный IP будет браться только от доверенного прокси (этап 1).
- `server` хранит `*pgxpool.Pool` и `*dbgen.Queries`. Транзакции: `Begin → q.WithTx(tx) → Commit`.

**Web** ([ux.md](ux.md), CLAUDE.md → «Фронтенд»):
- Основной цвет — indigo (выбран ради контраста; финальный цвет бренда пользователь может поменять).
- Копейки скрываются, если их нет. В ленте и списках суммы выравниваются по правому краю. В отчётах суммы округляются до рублей.
- Мобильная раскладка: ширина < `sm` **или** телефон в альбомной ориентации. Единый источник — `useMobileLayout()`. Пока окно открыто, его вид (sheet или модалка) не меняется.
- «Сегодня» считается по часовому поясу профиля (`todayIn(tz)`), `formatOpDate` требует `today` явно.
- Тема берётся из системы. Переключатель появится в настройках профиля на этапе 5.
- Эталоны скриншотов — только для win32. В CI идут только `@a11y`-тесты.

**Процесс:**
- Ветки: `<тип>/<область>-<суть>`. Слияние — `--no-ff` после «ок» пользователя (CLAUDE.md → «Git»).
- Исполнители — по умолчанию на **Sonnet**. Ревьюер на **Opus** — для новой функциональности. Правки после ревью проверяет сам PM, повторное ревью не заказывается.

## 4. Как PM ведёт задачу

1. **Постановка.** Цель, рамки («что НЕ делать»), заранее принятые решения, критерии приёмки со ссылками на документы, имя ветки, проверки перед отчётом, формат отчёта. Шаблон — в разделе 6.
2. **Исполнитель:** `Agent`, `isolation: "worktree"`, `run_in_background: true`, по умолчанию `model: "sonnet"`. Независимые задачи (например, `api/` и `web/`) можно запускать параллельно.
3. **Приёмка PM по отчёту исполнителя.** Не верить отчёту на слово:
   - в worktree прогнать сборку, линтер, тесты, генерацию без diff;
   - для UI — самому посмотреть скриншоты (инструмент `Read` открывает PNG).
4. **Ревью** — отдельный агент (шаблон в разделе 6), для новой функциональности. Ревьюер не правит код.
5. **Правки по ревью.** PM решает, что исправлять, и выбирает из предложенных вариантов. Список правок отправляется **тому же исполнителю** через `SendMessage`: у него сохранился контекст. Потом PM снова проверяет сам.
6. **Документация.** Правки в `docs/` и `CLAUDE.md`, которых не касаются ветки, PM делает в основной копии. Пробное слияние без изменений в репозитории: `git merge-tree --write-tree main <ветка>`.
7. **Отчёт пользователю.** Что сделано; что проверено и чем; что **не** проверено; решения PM, которые пользователь может оспорить. Затем запросить «ок» на слияние.
8. **Слияние.**
   - `git merge --no-ff -F <файл>` (`-F -` в этом окружении не работает, сообщение — через файл в scratchpad).
   - Проверки на `main`; убедиться, что `git diff <ветка> main -- api` (или `-- web`) пуст.
   - `git worktree remove`, `git branch -d`.
   - Обновить этот документ.

**Окружение (Windows):**
- Docker Desktop должен быть запущен.
- Postgres из `docker-compose.yml` общий для всех worktree. Тестовые БД изолированы, а dev-БД `pa` — общая.
- Playwright в разных worktree запускать на разных портах: `E2E_PORT=4181`.
- Go 1.25 в системе сам подтягивает toolchain 1.26 (`GOTOOLCHAIN=auto`). sqlc работает с `CGO_ENABLED=0`, используется WASM-парсер.

## 5. Следующие задачи

### 5.1 `feat/web-api-client` — API-клиент на фронте (готовая постановка)

**Цель.** Фронтенд получает типизированный клиент и хуки TanStack Query, сгенерированные из `api/openapi.yaml`. Это нужно, чтобы этап 1 начинался с готовой связки «контракт → клиент → форма».

**Решения:**
- **orval:**
  - вход — `../api/openapi.yaml`, выход — `web/src/shared/api/generated/` (коммитится);
  - клиент — `react-query`;
  - базовый адрес — `/api/v1` (в контракте он задан через `servers`, а пути описаны без префикса, см. api.md).
- **Свой `fetch`-мутатор** (`shared/api/http.ts`):
  - `credentials: 'same-origin'`;
  - ответ `application/problem+json` превращается в типизированный `ApiError`: `status`, `code`, `detail`, `fieldErrors: Record<string, string>` для будущих форм; запрос через `requestId` из `X-Request-Id`;
  - сетевая ошибка — отдельный вид ошибки.
- **Умолчания `QueryClient`:**
  - без повторов на 4xx, один повтор на сеть и 5xx;
  - разумный `staleTime`;
  - `refetchOnWindowFocus` оставить включённым.
- **Скрипты и CI:**
  - скрипт `pnpm generate:api`;
  - в `web.yml` — проверка, что сгенерированный код актуален (`git diff --exit-code`).
- **Применение:** `ApiStatus` (только DEV) показывает, кроме `/healthz`, число валют из `useListCurrencies` (или как назовёт orval) — как проверку связки. Других экранов не делать.

**Рамки:** бэкенд не трогать. Если контракту не хватает того, что нужно orval (`operationId`, теги), — сообщить в отчёте, не править контракт.

**Критерии приёмки:**
- Vitest-тесты мутатора с подменённым `fetch`: 200, 422 с `errors[]`, 404, 500 без тела, сетевая ошибка, не-JSON ответ.
- `pnpm generate:api` идемпотентен.
- Ручная проверка: `go run ./cmd/api` + `pnpm dev`, бейдж показывает валюты.
- Все проверки web из CLAUDE.md. Строки интерфейса — в `ru.ts`.
- Документация: раздел в CLAUDE.md («Фронтенд» и «Команды»), упоминание orval в api.md → «Инструменты генерации».

**Модель:** Sonnet. Ревью: PM сам (задача инфраструктурная и маленькая).

### 5.2 Этап 1 — черновик декомпозиции (уточнить перед стартом)

| Ветка | Содержание |
|---|---|
| `feat/api-auth` | `argon2id`, регистрация/вход/выход/`me`, сессии в Postgres (cookie `httpOnly`, `Secure`, `SameSite=Lax`), CSRF, middleware «текущий пользователь + `family_id`», создание семьи и категорий по умолчанию при регистрации (в транзакции), rate limit, реальный IP от доверенного прокси, часовой пояс профиля |

- выбрать почтовый сервис для production;
- тексты или ссылки на политику ПДн и пользовательское соглашение (пока можно заглушки);
