# Домашняя бухгалтерия — требования к MVP

> Статус: черновик v0.1 · 2026-11-13

## 1. Цель и рамки

Публичный SaaS для учёта личных и семейных финансов (аналог «Дребеденег»).

Главная ценность MVP:
1. **Быстрый ввод операций** — расход вносится за 3–5 секунд.
2. **Понятная картина** — куда уходят деньги и сколько их на счетах.
3. **Совместный учёт в семье** при сохранении приватности личных счетов.

Приоритеты требований:
- **P0** — без этого не запускаемся;
- **P1** — желательно в MVP, можно перенести на первый апдейт.

## 2. Технологический стек

| Слой | Выбор |
|---|---|
| Фронтенд | React + TypeScript, Vite (SPA), PWA через `vite-plugin-pwa` |
| UI | Mantine (`core`, `form`, `dates`, `charts`, `notifications`, `spotlight`) |
| Данные на клиенте | TanStack Query, React Router |
| Бэкенд | Go: `chi` (роутинг), `pgx` (драйвер БД), `sqlc` (типобезопасный SQL), `goose` (миграции) |
| Контракт API | OpenAPI 3 (contract-first): `oapi-codegen` для Go, `orval` для TS-клиента |
| БД | PostgreSQL |
| Инфраструктура | Docker Compose локально; хостинг в РФ (Yandex Cloud / Selectel / Timeweb) |
| Репозиторий | монорепо: `/api`, `/web`, `/docs` |

Лендинг (SEO) — отдельный проект позже, вне MVP.

## 3. Основные сущности

| Сущность | Описание |
|---|---|
| **Пользователь** | Аккаунт: e-mail, имя, пароль, часовой пояс |
| **Семья** | Общее пространство данных. Пользователь состоит **ровно в одной** семье. При регистрации создаётся семья из одного человека |
| **Участник семьи** | Связь пользователя с семьёй, роль: `owner` или `member` |
| **Счёт** | Место хранения денег. Валюта, тип, видимость (`shared` / `private`) |
| **Категория** | Двухуровневое дерево, отдельно для расходов и доходов. Общая на всю семью |
| **Операция** | Расход, доход, перевод (в т. ч. обмен валют) или корректировка остатка |
| **Валюта** | Справочник ISO 4217. В MVP включены RUB (базовая) и USD |
| **Курс** | Курс ЦБ РФ на дату, хранится вся история |
| **Приглашение** | Одноразовая ссылка-приглашение в семью |
| **Журнал изменений** | Кто, когда и что изменил или удалил |

## 4. Роли и видимость

| Действие | owner | member |
|---|---|---|
| Видеть общие счета и операции по ним | ✅ | ✅ |
| Видеть **чужие** личные счета и операции по ним | ❌ | ❌ |
| Создавать и редактировать операции на общих счетах | ✅ | ✅ |
| Создавать и редактировать общие счета, категории | ✅ | ✅ |
| Приглашать и исключать участников | ✅ | ❌ |
| Удалить семью | ✅ | ❌ |

**Правила видимости:**
- Личный счёт и все операции по нему видит только его владелец. Полностью скрыто, даже факт существования.
- **Перевод между личным и общим счётом.** Остальные видят операцию только на общем счёте: «Пополнение от Ивана» или «Снятие Иваном». Личный счёт не раскрывается. Редактировать такой перевод может только владелец личного счёта.
- Отчёты и итоговые балансы строятся **только по видимым пользователю счетам**. У каждого участника своя картина.

## 5. Функциональные требования

### 5.1 Регистрация и вход
- **[P0]** Регистрация по e-mail и паролю, подтверждение e-mail.
- **[P0]** Вход и выход, сброс пароля по e-mail.
- **[P0]** При регистрации — согласие на обработку ПДн и принятие пользовательского соглашения (чекбокс со ссылками на документы).
- **[P0]** Сессии на сервере (таблица в Postgres), идентификатор в `httpOnly`, `Secure`, `SameSite=Lax` cookie. Защита от CSRF.
- **[P0]** Ограничение частоты попыток входа и сброса пароля.
- **[P1]** Список активных сессий с возможностью завершить чужие.

### 5.2 Профиль
- **[P0]** Имя, e-mail, смена пароля, часовой пояс (определяется браузером, можно изменить).
- **[P0]** Удаление аккаунта со всеми данными (с подтверждением; перед удалением предлагается экспорт).

### 5.3 Семья
- **[P0]** При регистрации автоматически создаётся семья, пользователь в ней `owner`.
- **[P0]** Владелец создаёт ссылку-приглашение: одноразовая, срок жизни 7 дней, может её отозвать.
- **[P0]** По ссылке можно зарегистрироваться (сразу попадаешь в семью) или войти существующим аккаунтом (см. открытый вопрос Q1).
- **[P0]** Список участников, исключение участника владельцем, добавление и удаление второго владельца.
- **[P0]** Участник может покинуть семью — ему создаётся новая пустая семья (см. Q2).

### 5.4 Счета
- **[P0]** Поля: название, тип (`cash`, `card`, `bank_account`, `deposit`, `credit_card`, `other`), валюта (RUB/USD), начальный остаток, видимость (`shared` / `private`), «учитывать в общем балансе», цвет или иконка.
- **[P0]** Текущий остаток = начальный остаток + сумма операций.
- **[P0]** Кредитная карта может уходить в минус.
- **[P0]** Архивирование (счёт скрыт из списков и форм, история сохраняется). Удалить можно только счёт без операций.
- **[P0]** Ручная сортировка счетов.
- **[P0]** **Корректировка остатка**: пользователь вводит фактический остаток, система создаёт операцию-корректировку на разницу.
- **[P1]** Смена видимости `private` → `shared` и обратно (с предупреждением о том, кто что увидит).

### 5.5 Категории
- **[P0]** Два независимых дерева: расходы и доходы. Глубина — 2 уровня.
- **[P0]** Набор по умолчанию при создании семьи (~15 категорий расходов, ~5 доходов с подкатегориями).
- **[P0]** Создание, переименование, перемещение, архивирование.
- **[P0]** Удаление категории с операциями — только с переносом операций в другую категорию (по сути, слияние).
- **[P1]** Иконки и цвета категорий.

### 5.6 Операции
- **[P0]** Типы:
  - **Расход** / **Доход**: счёт, сумма, категория, дата, комментарий.
  - **Перевод**: счёт-источник, счёт-получатель, сумма списания, сумма зачисления. Если валюты счетов совпадают, сумма одна. Если различаются, это **обмен валют**: вводятся обе суммы, фактический курс вычисляется и показывается.
  - **Корректировка**: создаётся только через корректировку остатка (5.4).
- **[P0]** Дата — календарная дата без времени (по умолчанию «сегодня» в часовом поясе пользователя), отдельно хранится время создания.
- **[P0]** Каждая операция хранит автора (кто внёс).
- **[P0]** Редактирование, удаление (мягкое), дублирование.
- **[P0]** Все изменения и удаления пишутся в журнал изменений.
- **[P1]** Просмотр истории изменений конкретной операции.

### 5.7 Быстрый ввод
- **[P0]** Форма ввода доступна с главного экрана (desktop) и по кнопке «+» (mobile).
- **[P0]** Фокус сразу в поле суммы. Поле принимает арифметику: `350+120*2` → `590`.
- **[P0]** Категория — автодополнение по названию; частые категории пользователя показываются первыми.
- **[P0]** Счёт по умолчанию — последний использованный этим пользователем.
- **[P0]** `Enter` сохраняет, форма очищается, фокус возвращается в сумму. Тост с кнопкой «Отменить».
- **[P0]** Переключение «Расход / Доход / Перевод» вкладками.
- **[P1]** Горячие клавиши для переключения типа и даты (вчера/сегодня).

### 5.8 Лента операций
- **[P0]** Группировка по дням с итогом за день.
- **[P0]** Фильтры: период, тип, счета, категории (с подкатегориями), автор, поиск по комментарию.
- **[P0]** Подгрузка при прокрутке.
- **[P0]** Итог по отфильтрованным операциям (расходы, доходы, разница).
- **[P0]** Редактирование: inline на desktop, нижняя панель (bottom sheet) на mobile.
- **[P1]** Фильтр по диапазону суммы.

### 5.9 Валюты и курсы
- **[P0]** Базовая валюта семьи — **RUB** (в MVP не настраивается).
- **[P0]** Ежедневная загрузка курсов ЦБ РФ (USD, с запасом — EUR), хранение истории.
- **[P0]** Пересчёт в отчётах — **по курсу на дату операции**. Если курса на дату нет, берётся ближайший предыдущий.
- **[P0]** Итоговый баланс в рублях — по последнему доступному курсу.
- **[P0]** Суммы валютных счетов показываются в исходной валюте, рядом (там, где это уместно) — эквивалент в рублях.

### 5.10 Отчёты
Все суммы — в рублях, только по видимым пользователю счетам. Корректировки и переводы в отчёты о расходах и доходах не входят.
- **[P0]** **Расходы (или доходы) по категориям** за период: кольцевая диаграмма + таблица с раскрытием подкатегорий, доля в %. Клик по категории открывает ленту с этим фильтром.
- **[P0]** **Доходы и расходы по месяцам**: сгруппированные столбцы + линия разницы, по умолчанию 12 месяцев.
- **[P0]** **Динамика общего баланса**: линия, шаг — день, неделя или месяц в зависимости от периода.
- **[P0]** Фильтры: период (пресеты: текущий / прошлый месяц, год, произвольный), счета, участник.

### 5.11 Экспорт и импорт
- **[P0]** Экспорт операций в CSV (с учётом текущих фильтров) и полный экспорт всех видимых данных.
- **[P1]** Импорт CSV: загрузка файла → сопоставление колонок (дата, сумма, комментарий, категория) → выбор счёта → предпросмотр → импорт. Нераспознанные категории попадают в «Без категории».

## 6. Экраны

Навигация:
- **mobile** — нижняя панель: *Главная · Операции · [+] · Отчёты · Ещё*;
- **desktop** — боковое меню.

| Экран | Содержимое |
|---|---|
| Вход / регистрация | e-mail + пароль, сброс пароля |
| Главная | Общий баланс; список счетов (сворачиваемый); форма быстрого ввода (desktop); последние операции по дням |
| Операции | Фильтры, лента, итоги, редактирование |
| Отчёты | Вкладки: «По категориям», «По месяцам», «Баланс» |
| Счета | Список (общие и личные отдельно), создание и редактирование, корректировка остатка, архив |
| Настройки → Категории | Два дерева, перетаскивание, слияние |
| Настройки → Семья | Участники, приглашения |
| Настройки → Профиль | Данные, пароль, часовой пояс, удаление аккаунта |
| Настройки → Данные | Экспорт, импорт |
| Онбординг | После регистрации: создать первый счёт (с подсказками), кратко показать быстрый ввод |

## 7. Нефункциональные требования

### Деньги и данные
- Суммы хранятся в `bigint` в минимальных единицах валюты (копейки, центы) вместе с кодом валюты. Никаких `float`.
- Каждая строка доменных данных содержит `family_id`. Изоляция между семьями проверяется на уровне запросов и покрыта тестами.
- Мягкое удаление операций, счетов, категорий.

### Безопасность и юридические требования
- **152-ФЗ:** персональные данные хранятся на серверах в РФ. Публикуются политика обработки ПДн и пользовательское соглашение. До этапа 6 вместо текстов — заглушки; настоящие тексты нужны до запуска. Подаётся уведомление в Роскомнадзор об обработке ПДн. *Юридические детали проверить с юристом до запуска.*
- Пароли — `argon2id`. Только HTTPS. Заголовки безопасности (CSP, HSTS).
- Ограничение частоты запросов на чувствительных эндпоинтах.

### Производительность и надёжность
- API: p95 < 300 мс на типовых запросах при ~10 тыс. операций в семье.
- Ежедневные бэкапы БД с возможностью восстановления на момент времени (PITR).
- Структурированные логи, базовые метрики, отслеживание ошибок (Sentry или аналог).

### Клиент
- **Качественный UI/UX — ключевое конкурентное преимущество.** Принципы, стандарты и чек-лист готовности экрана — в [ux.md](ux.md), они обязательны.
- Mobile-first вёрстка, поддержка последних 2 версий Chrome, Safari (включая iOS), Firefox, Edge.
- PWA: устанавливается на домашний экран, кэширует оболочку приложения. Офлайн-ввод — вне MVP.
- Светлая и тёмная тема (Mantine даёт это почти бесплатно).
- Интерфейс только на русском, но строки вынесены в отдельные файлы, чтобы добавить i18n позже.

### Архитектура на будущее
- API — единственный источник логики. Будущий Telegram-бот и мобильное приложение — просто ещё клиенты.
- У семьи есть поле `plan` для будущего биллинга.

## 8. Вне рамок MVP

- Бюджеты и лимиты по категориям.
- Регулярные и запланированные платежи, напоминания.
- Долги.
- Теги.
- Импорт выписок конкретных банков, разбор SMS и push-уведомлений.
- Сканирование QR-кодов чеков (ФНС).
- Цели и накопления.
- Выбор базовой валюты, валюты кроме RUB/USD/EUR.
- Несколько семей у одного пользователя.
- Офлайн-ввод с синхронизацией.
- Вход через Яндекс ID и Google (OAuth 2.0 / OIDC) и управление способами входа. Схема БД к этому готова (`user_identities`).
- Telegram-бот (первый кандидат после MVP).
- Нативное мобильное приложение.
- Биллинг и платные тарифы.

## 9. Открытые вопросы

Все вопросы закрыты: 2026-11-19 пользователь утвердил предложения по умолчанию.

| # | Вопрос | Решение |
|---|---|---|
| Q1 | Существующий пользователь принимает приглашение, а в его текущей семье уже есть данные. Что с ними? | В MVP: принять можно, только если он единственный участник своей семьи. После явного подтверждения (и предложения сделать экспорт) старая семья удаляется. Перенос данных — позже |
| Q2 | Участник покидает семью или его исключают. Что с его личными счетами? | Личные счета и операции остаются в семье в архиве, никому не видны. Перед выходом предлагается экспорт. Перенос — позже |
| Q3 | Владелец удаляет аккаунт, а в семье есть другие участники | Нужно сначала передать роль владельца (или назначить второго владельца). Без этого удаление заблокировано |
| Q4 | Может ли участник редактировать чужие операции на общих счетах? | Да, все правки пишутся в журнал изменений |
