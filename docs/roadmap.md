# План разработки MVP

> Статус: черновик v0.1 · 2026-11-18

Этапы идут по порядку, каждый заканчивается работающим вертикальным срезом (БД → API → UI). Каждый экран считается готовым только по чек-листу из [ux.md](ux.md#9-процесс-как-обеспечиваем-качество) — UX не откладывается на «потом отполируем».

## Этап 0. Фундамент

**Бэкенд и контракт**
- OpenAPI-спецификация (`api/openapi.yaml`), генерация `oapi-codegen` (Go) и `orval` (TS-клиент + хуки TanStack Query).
- `sqlc` для запросов, общий формат ошибок API (RFC 9457), проверка запросов по контракту, структурированные логи.
- Доменные маршруты под префиксом `/api/v1`. Соглашения — в [api.md](api.md).
- Тестовая инфраструктура: интеграционные тесты на реальном Postgres (testcontainers или отдельная БД), тесты изоляции семей.

**Дизайн-система** (до первого настоящего экрана)
- Токены в `theme.ts`: цвета, шкала отступов, типографика, радиусы; локальный шрифт Inter (`@fontsource`), Tabler Icons.
- Оболочка: нижняя панель на mobile (*Главная · Операции · [+] · Отчёты · Ещё*), боковое меню на desktop.
- Базовые компоненты: `Money`, `EmptyState`, скелетоны, тосты с «Отменить», bottom sheet / модалка (адаптивная).
- Файлы локализации и форматтеры дат/сумм.
- Storybook для компонентов; Playwright (скриншоты, 375/1280, светлая/тёмная) и `axe` в CI.
- Линтер, форматтер, CI: сборка, тесты, линт для `api` и `web`.

## Этап 1. Авторизация и онбординг
- Регистрация / вход по e-mail, подтверждение e-mail, сброс пароля, `argon2id`, сессии в Postgres, CSRF, rate limit.
- Middleware текущего пользователя, `family_id` и видимости счетов.
- Реальный IP клиента только из заголовков доверенного прокси (нужно для rate limit по IP).
- Часовой пояс профиля — источник «сегодня» на клиенте (`todayIn`).
- Создание семьи и набора категорий по умолчанию при регистрации.
- **UX:** экраны входа без лишних полей (вход и регистрация — одна форма с переключением), понятные ошибки, сохранение введённого при ошибке. Онбординг перенесён в конец этапа 2: ему нужны счета.

## Этап 2. Счета и категории
- CRUD счетов, архив, ручная сортировка, корректировка остатка, расчёт остатков.
- Два дерева категорий, перемещение, архив, слияние.
- **UX:** компоненты `AccountPicker` и `CategoryPicker` (используются дальше в быстром вводе); перетаскивание с поддержкой клавиатуры и касаний; пустые состояния.
- **Онбординг** (в конце этапа, перенесён из этапа 1): «первый счёт → показать быстрый ввод». Цель — первая операция за ≤ 2 минуты после регистрации.

## Этап 3. Быстрый ввод и лента (ключевой этап)
- API операций: создание, редактирование, мягкое удаление, дублирование, журнал изменений, видимость переводов.
- Лента с группировкой по дням, фильтрами, бесконечной прокруткой, итогами.
- **UX:** основной объём дизайнерской работы проекта.
  - `AmountInput` с калькулятором, чипы частых категорий, умные значения по умолчанию.
  - Оптимистичные обновления и отмена через тост.
  - Inline-редактирование на desktop, bottom sheet на mobile.
  - **Юзабилити-тест №1** с 3–5 людьми: замер времени и касаний на ввод расхода (цель ≤ 5 с, ≤ 3 касания). Доработки по итогам — часть этапа, а не бэклог.
  - *2026-11-24: этап закрыт без юзабилити-теста — тест отложен в бэклог решением пользователя (протокол — [usability-test-1.md](usability-test-1.md), handoff, техдолг №47).*

## Этап 4. Валюты и отчёты
- Загрузка курсов ЦБ по расписанию, пересчёт по курсу на дату.
- Отчёты: по категориям, по месяцам, динамика баланса; фильтры и пресеты периодов.
- **UX:** вывод текстом над графиком («потрачено на 12% меньше, чем в октябре»), интерактивные графики с переходом в ленту, ленивая загрузка библиотеки графиков, графики читаемы на 375 px и в тёмной теме.

## Этап 5. Семья, профиль, данные
- Приглашения, участники, роли, выход из семьи (Q1–Q3).
- Профиль, смена пароля, часовой пояс, удаление аккаунта.
- Экспорт CSV; импорт CSV [P1].
- **UX:** понятное объяснение приватности («этот счёт видите только вы»), предупреждения при смене видимости счёта, мастер импорта с предпросмотром.

## Этап 6. Подготовка к запуску
- PWA: манифест, иконки, кэш оболочки, плашка «нет соединения».
- **UX-аудит всего приложения:** проход по чек-листу каждого экрана, аудит доступности, Lighthouse/Web Vitals на среднем Android (LCP < 2,5 с, INP < 200 мс), бюджет бандла.
- **Юзабилити-тест №2** — полный сценарий от регистрации до отчёта.
- Безопасность: CSP, HSTS, заголовки; бэкапы с PITR; мониторинг ошибок.
- Почта: выбор сервиса для production (российский провайдер — адреса пользователей являются ПДн), SPF/DKIM/DMARC для домена, проверка доставки писем в Gmail, Mail.ru и Яндекс.
- Юридическое: политика ПДн, соглашение, уведомление в РКН, хостинг в РФ.
